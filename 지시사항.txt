- 라우터별 인증 강제 불일치
  - 일부 라우트는 미들웨어 없이 수동 검사(또는 미검증)로 운영됨. 예: 유명인물 댓글/좋아요 라우트는 `authMiddleware` 미적용, 내부에서 `getUserFromToken` 사용.

### API 설계/일관성(Major)
- 응답 필드 언어·케이스 혼재
  - 한국어 키(예: `내용`, `작성자`)와 영어/camelCase가 혼재. 팀 규칙상 camelCase 유지 권장 [[memory:4718312]].
  - 조치: 내부 도메인은 영어 camelCase 통일, 다국어는 UI 레벨에서 표시 문자열만 지역화. 필요 시 Response Mapper 도입.
- 스키마와 실제 응답 형태 불일치
  - 예: 유명인물 목록/상세는 한국어 키 반환인데, OpenAPI 스키마는 영문 `CelebritySchema` 구조를 기대. 코드 주석의 “안됨”의 원인.
  - 예: `CommentFieldsSchema`의 `작성자ID`가 string 스키마인데 실제 number 반환.
- 보안 스키마 누락
  - OpenAPI에 `BearerAuth` security scheme 미등록 상태로 보임. Swagger UI에서 인증 테스트 곤란. 문서 생성 시 `components.securitySchemes` 추가 필요.
